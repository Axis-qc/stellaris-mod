## 工作流程

- **先查找，后编写**：修改或新增功能前，先在本项目 mod 文件中搜索相关实现；若未找到，再搜索游戏原版目录；必要时可查阅社区已知范例（如
  Stellaris wiki 或主流 mod 源码）。禁止凭空编写伪代码。
- **精确编辑**：修改已有文件时，必须使用 Edit 工具进行精准的局部修改，禁止整文件替换或使用 Write 覆盖已有文件。
- **按需读取**：只读取与当前任务直接相关的文件，禁止批量读取无关文件，避免上下文膨胀导致会话失败。
- **遇歧义先询问**：无论在计划阶段还是实施阶段，遇到任何问题、歧义点或存在多种可行方案时，必须优先询问用户，得到用户确切回复后才能继续。禁止随意推测用户意图或自行选择方案。
- **先计划后实施**：对于非简单修改任务（例如新增一个事件链、一套政策、一项机制），必须先制定计划。计划须由用户审阅并明确批准后，方可进入实施阶段。
- **不确定的语法不编造**：若遇到不确定的触发器、效果、修饰符或作用域，应主动询问用户或查阅官方文档，不得自行发明语法。
- **基于记忆对话**：每次对话开始时必须先读取记忆，基于已有记忆进行交流。
- **实时更新记忆**：对话过程中有新信息或重要上下文时，应及时写入记忆，确保后续对话能延续。

## 版本控制

- 使用 git 管理版本。
- **禁止创建任何备份文件**（如 .bak、.old、~ 结尾的文件）。版本回退一律使用 git。
- **提交规范**：每次功能修改或 bug 修复对应一个 commit。提交信息格式为 `<类型>: 简短描述`（类型可选 `feat`、`fix`、`docs`、
  `refactor`、`localize` 等）。进行重要修改前，应确保当前工作区已 commit 或 stash，防止意外丢失。

## 项目结构

- `.mod` 文件是 mod 元数据描述文件，对应同名目录为 mod 内容。注意 `descriptor.mod`（发布用）与根目录下的 `.mod`
  文件（启动器识别用）需保持同步。
- mod 内容结构通常与游戏原版目录结构平行（common/、events/、localisation/、gfx/、sound/ 等）。
- 游戏原版数据文件位于 `G:\SteamLibrary\steamapps\common\Stellaris` 下的对应子目录中。

## 编码与格式

- **文件编码**：所有文本文件（`.txt`、`.yml`、`.gui`、`.mod` 等）统一使用 **UTF-8 without BOM**。不要使用 ANSI 或带 BOM 的
  UTF-8，否则游戏可能读取失败。
- **行尾符**：使用 LF（Unix 风格），不推荐 CRLF。
- **缩进与空格**：建议使用制表符（Tab）或 4 个空格，与目标文件现有风格保持一致。避免行尾多余空格。

## 命名与 ID 规范

- 为避免与其他 mod 或 DLC 冲突，所有自定义 key、事件 ID、国家 ID、科技 ID、特性 ID 等应添加专属前缀（例如 `my_`
  或作者缩写）。禁止使用纯数字或无意义名称。
- 文件名应能体现内容，例如 `my_mod_events.txt`，不要使用 `new_1.txt`。
- 本地化 key 格式：`<id前缀>_<描述>`，如 `my_mod_tech_1:0 "科技名"`。

## 本地化（Localisation）

- 修改或新增文本时，必须同步更新对应的本地化文件（`localisation/english/*.yml` 及（若有）`simp_chinese/*.yml`）。
- 注意 YAML 文件格式：以 `l_english:` 或 `l_simp_chinese:` 开头，每个条目为 ` key:0 "文本"`（冒号后有一个空格，数字 `0`
  表示版本）。
- 不要在值区域以外使用中文引号，必须使用英文双引号。
- 若某一语言缺少翻译，至少提供英文 fallback。

## 调试与验证

- 修改脚本文件后，可通过启动游戏或运行 `stellaris` 控制台（若支持）检查错误日志。错误日志通常位于
  `Documents/Paradox Interactive/Stellaris/logs/error.log`。
- 遇到报错时，优先根据日志内容定位到具体文件及行号，再提出解决方案。
- 对于复杂脚本（如事件、决议），可建议用户手动测试关键路径。

## 依赖与兼容性

- 若 mod 需要其他 DLC 或 mod 作为依赖，必须在 `.mod` 文件中注明 `dependencies` 或 `supported_version`。
- 修改原版文件时，优先使用“覆盖”结构（相同路径与文件名）而非直接改动原版内容。永远不要修改游戏原版目录下的任何文件。
