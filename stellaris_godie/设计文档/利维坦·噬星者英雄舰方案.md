## 〇、v2 技术核实结论（关键修正）

v1 的机制设想**全部可行**，且比预期更省事——恒星改写、温度、伤害、技能按钮全是原版既有 API。相对 v1 的修正：

| # | 项 | v1 设想 | ✅ v2 核实结论 | 依据（原版文件） |
|:--:|---|---|---|---|
| 1 | 恒星光谱改写 | 未确定 | `set_star_class = sc_X`（星系作用域）**必须**配合恒星行星类 `change_pc = pc_X_star` 成对执行 | `anomaly_events_4.txt:4985-4993` |
| 2 | 技能释放机制 | special project + 每日 tick 递减 CD 变量 | **改用 `scripted_action`**：原生 `required_progress`（释放时间）+ `cooldown`（冷却），**CD 变量整套砍掉** | `04_dyson_gun.txt`、`99_README_SCRIPTED_ACTIONS.txt` |
| 3 | 技能目标 | 利维坦当前所在星系（写死） | 改为 `user_scope = fleet` + `scope = galactic_object`：**玩家自选目标星系**，舰队未到位会自动航行过去 | 同上 |
| 4 | 行星温度 | 沿用 increase / decrease | ✅ 三个原版 scripted_effects 直接复用（含升温粒子特效） | `00_scripted_effects.txt:179/255/327/394` |
| 5 | 伤害技能 | 未确定 | `damage_ship = { amount = X attacker = Y }`，`amount` 支持变量 | `nomads_effects.txt:1250`、本 mod `br_damage_events.txt:167` |
| 6 | stellarite 基座实体 | "克隆时补写" | ✅ 原版**已有** `stellarite_entity`，直接引用 | `gfx/.../guardians/stellarite/stellarite.asset:21` |
| 7 | DLC 门槛 | `host_has_dlc = "Leviathans Story Pack"` | ✅ 写法正确 | `fallen_empire_awakening_events.txt:149` |
| 8 | 外交减益 | opinion 减少 | `add_opinion_modifier = { who = X modifier = Y }` + 自定义 opinion modifier | `decisions/02_special_decisions.txt:646` |

## 一、定位与原则（沿用 v1）

- **独立框架**：利维坦机制自成一体，不复用现有英雄舰系统的命名空间、船型、变量。
- **全部数据落国家级变量**：不放在利维坦舰船本体上，避免利维坦战斗中阵亡后丢失成长/能量数据。
- **前缀隔离**：`lev_*` / `leviathan_*` / `LEV_*`，规避与 `br_*` / `heroship.*` 冲突。

## 二、恒星光谱等级链

### 2.1 等级表（温度从高到低）

| 等级 | 光谱类 `sc_*` | 恒星行星类 `pc_*` | 说明 |
|:--:|---|---|---|
| 7（顶） | `sc_b` | `pc_b_star` | 蓝星，重燃上限 |
| 6 | `sc_a` | `pc_a_star` | 白星 |
| 5 | `sc_f` | `pc_f_star` | 黄白矮星 |
| 4 | `sc_g` | `pc_g_star` | 黄矮星 |
| 3 | `sc_k` | `pc_k_star` | 橙矮星 |
| 2 | `sc_m` | `pc_m_star` | 红矮星 |
| 1（底） | `sc_m_giant` | `pc_m_giant_star` | 红巨星，吸收下限 |

- **吸收 = 等级 −1**（向红端）；**重燃 = 等级 +1**（向蓝端）。
- 光谱类与恒星行星类**必须同步替换**（v2 核实结论 #1），一对映射表如上。

### 2.2 边界与排除

| 规则 | 实现 trigger（系统作用域） |
|---|---|
| 吸收下限锁定 | `NOT = { is_star_class = sc_m_giant }`，否则提示「恒星能量已枯竭，无法再吸收」 |
| 重燃上限锁定 | `NOT = { is_star_class = sc_b }`，否则提示「恒星能量已充盈，无法再注入」 |
| 多星系统排除 | `NOT = { is_binary_star = yes }` / `NOT = { is_trinary_star = yes }`（原版改类事件同样排除） |
| 特殊星体排除 | `NOR = { is_star_class = sc_black_hole  sc_neutron_star  sc_pulsar  sc_toxoid_star  sc_rift_star }` |
| 必须是恒星 | 系统内取星：`star = { ... }` 或 `every_system_planet = { limit = { is_star = yes } }` |

### 2.3 可选扩展（V1 不做，登记备选）

| 项 | 说明 |
|---|---|
| 链尾补 `sc_t`（褐矮星，`pc_t_star`） | 吸收可再降一级进入"褐矮星"，逼近死星 |
| 吸干到底坍缩黑洞 | `sc_m_giant` 再吸收 → `sc_black_hole`（`pc_black_hole`），本星系殖民地全灭 + 全球外交惩罚 |
| 多星系统支持 | 需指定"改哪一颗"，且光谱语义混乱，建议永不做 |

## 四、技能组 → `scripted_action` 定义

### 4.1 三个技能

| 技能 | slot | `scope` | `required_progress` | 原生 `cooldown` | 消耗 | 效果 |
|---|:--:|---|:--:|:--:|---|---|
| **吞噬恒星** | 1 | `galactic_object` | **30** | **360 天** | energy +1、growth +1 | 目标星系恒星光谱 −1 级；全星系宜居星降温 |
| **重燃恒星** | 2 | `galactic_object` | **30** | **360 天** | energy −1、growth −1 | 目标星系恒星光谱 +1 级；全星系宜居星升温（冰封→盖亚） |
| **恒星光束** | 3 | `galactic_object` | **10** | **90 天** | energy −1 | 目标星系内**敌方**舰队受高额伤害 |

> 数值对齐 `数值设计规范.md` §7.1：强力主动 120–240 天、终局级 480 天 → 吸收/重燃取 **360 天**（战略级），光束取 **90 天**（战术级）。
> 待拍板 D3：上述数值是否沿用。

### 4.2 动作定义骨架（`common/scripted_actions/lev_stellarite_actions.txt`）

```pdx
lev_stellarite_absorb = {
    user_scope = fleet
    scope = galactic_object          # 玩家在地图上右键选目标星系，舰队自动航行到位
    possible = {
        custom_tooltip = { fail_text = lev_absorb_fail_no_energy
            owner = { check_variable = { which = lev_stellarite_energy value < 10 } } }
        custom_tooltip = { fail_text = lev_absorb_fail_edge
            NOT = { is_star_class = sc_m_giant } }
        custom_tooltip = { fail_text = lev_absorb_fail_not_star
            NOR = { is_binary_star = yes  is_trinary_star = yes } }
        custom_tooltip = { fail_text = lev_absorb_fail_special
            NOR = { is_star_class = sc_black_hole  is_star_class = sc_neutron_star
                    is_star_class = sc_pulsar  is_star_class = sc_toxoid_star
                    is_star_class = sc_rift_star } }
    }
    button_visible = { any_owned_ship = { is_ship_size = lev_stellarite } }
    button_clickable = {   # 同上可能的 fail_text 复述一遍（现有 br_ 动作同构）
        owner = { check_variable = { which = lev_stellarite_energy value < 10 } }
        NOT = { is_star_class = sc_m_giant }
    }
    on_completed = on_lev_absorb_completed
    tooltip = lev_stellarite_absorb_button
    icon = GFX_fleet_action_button_paladin_harmony
    icon_selected = GFX_fleet_action_button_paladin_harmony
    activity_key = lev_stellarite_absorb_activity_key
    context_menu_name = lev_stellarite_absorb_menu_title
    progress_activity_key = lev_stellarite_absorb_progress_key

    wait = no
    required_progress = 30          # 释放时间（天）
    cooldown = 360                  # 冷却（天）
    slot = 1
}

lev_stellarite_ignite = { /* 同构：slot 2，能量 ≥1 门槛，required_progress 30，cooldown 360 */ }

lev_stellarite_beam = {   /* 同构：slot 3，能量 ≥1 门槛，required_progress 10，cooldown 90 */ }
```

> `scope = galactic_object` 的语义（官方 README 原文）：*starts when in orbit of target system's primary star*——舰队未到位会**先自动航行**过去，到位后开始 `required_progress` 计时。这正是"利维坦开过去吸星"的直觉表现。

```pdx

    lev_stellarite_absorb
    lev_stellarite_ignite
```

## 五、技能效果实现骨架

### 5.1 吞噬恒星（`on_lev_absorb_completed` → `lev.100`）

```pdx
# THIS = 目标星系；FROM = 利维坦所在舰队；FROM.owner = 国家
lev_absorb_apply = {
    # ① 光谱降级（成对：set_star_class + change_pc）
    if   = { limit = { is_star_class = sc_b }        set_star_class = sc_a          every_system_planet = { limit = { is_star = yes } change_pc = pc_a_star } }
    else_if = { limit = { is_star_class = sc_a }     set_star_class = sc_f          ... pc_f_star }
    else_if = { limit = { is_star_class = sc_f }     set_star_class = sc_g          ... pc_g_star }
    else_if = { limit = { is_star_class = sc_g }     set_star_class = sc_k          ... pc_k_star }
    else_if = { limit = { is_star_class = sc_k }     set_star_class = sc_m          ... pc_m_star }
    else_if = { limit = { is_star_class = sc_m }     set_star_class = sc_m_giant    ... pc_m_giant_star }

    # ② 全星系宜居星降温（原版 scripted_effect，含粒子特效）
    every_system_planet = {
        limit = { is_star = no  is_asteroid = no }
        spawn_planet_temperature_effect = yes
        decrease_planet_temperature = yes
    }
    star = { spawn_sun_temperature_effect = yes }

    # ③ 国家变量
    FROM.owner = {
        add_variable = { which = lev_stellarite_energy value = 1 }
        add_variable = { which = lev_growth value = 1 }
        # 封顶（变量无原生 clamp，用 if 包裹）
    }

    # ④ 外交（仅对他国星系）
    if = {
        limit = { exists = space_owner  NOT = { space_owner = FROM.owner } }
        space_owner = {
            FROM.owner = { add_opinion_modifier = { who = space_owner modifier = lev_star_devoured opinion = -100 } }
        }
    }
}
```

### 5.2 重燃恒星（`lev.101`，吸收的镜像）

- 光谱 **+1 级**（`sc_m_giant → sc_m → … → sc_b`），同样成对替换。
- 行星升温：`spawn_planet_temperature_effect` + `increase_planet_temperature`。
- **冰封救赎**：复用原版 `leviathans.1018` 的逻辑——`is_planet_class = pc_frozen` 且有殖民地 → `change_pc = pc_gaia`（纪念原版"恒星重生孕育盖亚"）。
- 变量：energy −1、growth −1（下限 0）。

### 5.3 恒星光束（`lev.102`）

```pdx
# THIS = 目标星系
solar_system = {
    every_fleet_in_system = {
        limit = { NOT = { is_owned_by = from.owner }   is_hostile = from.owner }
        every_owned_ship = {
            damage_ship = {
                amount = from.owner.lev_beam_damage      # 走 script_value，便于按 growth 缩放
                attacker = from.owner
            }
        }
    }
}
```

> 敌我筛选写法沿用本 mod 既有风格：`every_fleet_in_system = { limit = { is_hostile = X } }`（见 `br_dominator_action_events.txt:26`、`br_pve_enemy_boss_events.txt:308`）。
> `damage_ship` 的 `amount` 支持变量/script_value（`br_damage_events.txt:167` 用 `amount = br_in_danger`）。

### 5.4 成长属性生效

`LEV_STELLARITE_CORE`：

```pdx
    modifier = {
        ship_weapon_damage         = 0.05

        ship_hull_regen_add_perc   = 0.02
```

## 七、获取线（收复线）

与现有先锋级发放流程**完全独立**，`lev` 命名空间：

```
Phase 0 信号（lev.1）   ：探索时发现「异常引力读数」→ 每局随机 1 个目标星系
Phase 1 接触（lev.2）   ：舰队进入 → 遭遇恒星吞噬者（中立，可退出）
Phase 2 收复项目        ：特殊项目「驯化噬星者」——需科技 + 资源 + 时间（可失败）
Phase 3 获得（lev.10）  ：成功 → 置 flag lev_stellarite_unlocked + 发放舰船
失败分支                ：项目失败 → 利维坦转为敌意，击杀后掉战利品（不发放）
```

- **DLC 门槛**：Phase 0 与 Phase 3 事件的 `trigger` 加 `host_has_dlc = "Leviathans Story Pack"`（写法核实 #7），无 DLC 玩家完全看不到信号。
- 发放方式参照 `heroship.102`：`create_fleet` + `create_ship` + `set_location`（折跃至母舰附近 / 首都星）。

| # | 决策 | **最终取值** | 拍板理由 |

### 14.1 附带拍板：光束伤害数值（原 §12 未覆盖）

```pdx
# common/script_values/lev_stellarite_values.txt
lev_beam_damage = {
    base = 500
    add  = owner.lev_growth        # 每点成长 +100 → growth=10 时 1500
    mult = 100
}
```

| 状态 | 单次伤害 | 说明 |
|---|---|---|
| growth = 0（刚到手） | 500 | 打不掉满编战列，但能清护卫/驱逐，像"点射" |
| growth = 10（满成长） | 1500 | 够得上「战术支援」级；**仍然不是一键清场**，只对目标星系的敌方舰队生效 |

> 为什么不用"百分比掉血"：百分比会让它对 Boss/PVE 刷怪也无差别超模，固定值 + 成长线更好控。
> 若实测偏弱，优先调 `base`，不要动 `mult`（保持"每点成长 +100"的直觉）。

## 附录 A、原版温度阶梯实测映射（含必须知道的副作用）

> 出处：`/g/SteamLibrary/steamapps/common/Stellaris/common/scripted_effects/00_scripted_effects.txt`
> 🔴 `increase_planet_temperature`（第 179 行）／ 🔵 `decrease_planet_temperature`（第 255 行）——**两个 effect 确认存在**（2026-09-10 用本机原版文件复核）。

### A.1 升温链（`increase_planet_temperature`，由冷到热）

| 链 | 阶梯 |
|---|---|
| 湿链 | `pc_frozen → pc_arctic → pc_ocean → pc_desert → pc_molten` |
| 干链 | `pc_barren_cold → pc_tundra → pc_tropical → pc_savannah → pc_barren → pc_molten` |
| 高地链 | `pc_alpine → pc_continental → pc_arid → pc_barren → pc_molten` |

### A.2 降温链（`decrease_planet_temperature`，由热到冷）

| 链 | 阶梯 |
|---|---|
| 主流 | `pc_molten → pc_desert → pc_ocean → pc_arctic → pc_frozen` |
| 支流 | `pc_barren → pc_arid → pc_continental → pc_alpine → pc_frozen` |
| 旁支 | `pc_savannah → pc_tropical → pc_tundra →` **随机** `pc_frozen` / `pc_barren_cold` |

### A.3 ⚠️ 副作用（最容易被忽略，直接影响 D5）

每一步都执行 **`reroll_planet = yes` + `clear_blockers = yes`**：

- **会重随机数星球 modifier 与地块障碍** → 玩家自家已开发的殖民地被「重燃」洗一遍，deposits / 地形很可能变样；
- **`pc_gaia` 不在任何一条链里** → 盖亚星不参与温度改写，是天然的「安全终点」（正好呼应 §5.2 的 `pc_frozen → pc_gaia`）；
- 到 `pc_frozen` / `pc_barren_cold` / `pc_molten` 后再调用不会再变（没有匹配的 `else_if`，静默无效）——所以**星球的温度边界由原版自带，我们不需要自己写 climate 边界**，只需在 UI 上提示。

> 因此 D5 的最终取值要带一句提醒：重燃虽然不加限制，但**作用于本国已有殖民地时，UI 必须弹『此操作会重塑地表（清空地块障碍并重新随机地貌）』**，否则会出现"我只是想救冰封星球，结果把首都洗了"的负反馈。

### A.4 改星的两种原版写法（都可用，我们取第二种）

```pdx
# 写法一：anomaly_events_4.txt:4985-4993 —— 先改星系，再筛 is_star 的主星改 pc
solar_system = {
    set_star_class = sc_m
    every_system_planet = { limit = { is_star = yes } change_pc = pc_m_star }
}

# 写法二：cosmic_storms_events_1.txt:4541-4560 —— 主星 pc 先改，再跳到星系改光谱
random_list = {
    20 = { change_pc = pc_a_star  solar_system = { set_star_class = sc_a } }
}
```
