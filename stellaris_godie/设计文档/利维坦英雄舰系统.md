# 利维坦英雄舰系统（Leviathan Hero Ship）

> 复用原版利维坦模型做玩家英雄舰：模型/动画零成本，只需设计技能组与成长属性。
> 本档为设计稿（2026-08 拟定），实现前需确认文末「待拍板的决策」。
> 数值基准：`数值设计规范.md`；与现有英雄舰系统的关系：`总规范.md`。

---

## 一、系统定位

### 1.1 一句话

**利维坦英雄舰** = 用原版利维坦的 3D 模型 + 区段实体，克隆出玩家可拥有、可升级、带独立技能组的英雄舰。每条利维坦 = 一艘"自带核心的英雄舰"。

### 1.2 与现有英雄舰系统（先锋级）的关系

现有系统（`总规范.md`）：

* 玩家拥有 1 艘先锋级 `br_vanguard`（泰坦模型）
* 核心选择（火力/防御/航母）决定技能组
* 国家级等级变量 `br_hero_level` / `br_hero_xp`，技能倍率 `br_hero_ship_skill_{1/2/3}_mult`

利维坦英雄舰的定位（**推荐方案，见 §7 决策 D1**）：

* 利维坦是**英雄舰的进阶形态**：玩家收复利维坦后，先锋级退役，利维坦继承英雄舰等级（等级延续，不重练）
* 利维坦自带完整技能组（2 主动 + 2 被动 + 2 大招），**不再需要选核心**——利维坦本身就是核心
* 玩家始终保持单英雄舰，等级/倍率/技能 UI 全部复用现有国家级架构，改动最小

> 备选方案（并存多英雄舰）见 §7 D1，需扩展等级与 UI 架构，列为 V2。

## 二、可行性结论（已调查确认 [已实现]）

### 2.1 模型复用机制

原版利维坦模型分两层（`gfx/models/ships/guardians/`）：

| 层 | 作用 | 例（以太巨龙） |
|---|---|---|
| 基座实体 | 定位器/命中判定 | `space_dragon_red_entity`（ship_size 的 `entity` 字段引用） |
| 区段实体 | 实际模型+动画 | `space_dragon_red_section_entity`（区段模板引用） |
**原版先例**：`24_reanimated_leviathans.txt` 的复活利维坦就是玩家拥有、`entity` + 区段实体组合渲染的；`27_biogenesis_crisis.txt` 的巨兽（kaiju）更是 `hero_ship = {}` 块 + 玩家拥有的英雄舰。**模型复用零成本，已证实可行。**

## 三、舰船架构设计

### 3.1 原则：克隆，不碰原版

**绝对不修改 `11_leviathans.txt` 等原版文件**——那会破坏原版利维坦遭遇（守卫者 AI、剧情事件依赖原版 ship_size 名）。全部新写克隆文件：

| 新文件 | 内容 |
|---|---|
| `common/ship_sizes/br_leviathan_ships.txt` | 每个利维坦一个克隆 ship_size（命名 `br_leviathan_<名>`） |
| `common/section_templates/br_leviathan_sections.txt` | 克隆区段模板（`ship_size = br_leviathan_<名>`，引用原版区段实体） |
| `common/component_templates/br_leviathan_cores.txt` | 每利维坦专属技能核心组件（挂主动/被动/大招 scripted_action） |
| `common/static_modifiers/br_leviathan_buffs.txt` | 技能 modifier 定义 |
| `events/leviathan_acquire_events.txt` | 独立收复线事件 |
| `events/leviathan_skill_events.txt` | 技能触发事件 |
| `localisation/simp_chinese/br_leviathan_l_simp_chinese.yml` | 本地化（**UTF-8 BOM**） |
### 3.2 ship_size 克隆骨架（以以太巨龙为例）

```pdx
br_leviathan_drake = {
  entity = "space_dragon_red_entity"  # 基座实体（原版）
  can_be_inspected = yes
  hull_scale = 1  # 原版比例即可，可调
  max_speed = 100
  acceleration = 0.3
  rotation_speed = 0.4
  collision_radius = 15
  max_hitpoints = 4000  # 数值档位见 §5，不沿用原版 15 万
  combat_size_multiplier = 32
  size_multiplier = 32
  fleet_slot_size = 8
  section_slots = { "mid" = { locator = "part1" } }
  num_target_locators = 4
  never_lost = yes
  never_mia = yes
  is_space_station = no
  class = shipclass_military
  is_designable = yes  # 决策 D4：可设计，玩家可装配武器
  required_component_set = "br_hero_ship_Core"  # 复用英雄舰核心槽
  hero_ship = {
  hero_ship_fleet_background = "GFX_fleet_view_behemoth_stage_2"  # 复用原版背景
  capabilities = { can_repair can_upgrade }
  }
  components_add_to_cost = no
  resources = { ... }  # 按先锋级档位
  potential_country = { has_country_flag = br_leviathan_drake_unlocked }
}
```

### 3.3 区段模板克隆（复用原版区段实体 + 槽位）

原版龙区段（`space_dragon_red_key`）自带 1 XL + 8 中 + 4 点防 + 2 辅助 + 4 大型辅助槽，武器定位器在龙翼上。克隆时保留原版槽位布局、替换 `ship_size`：

```pdx
ship_section_template = {
  key = "br_leviathan_drake_key"
  ship_size = br_leviathan_drake
  fits_on_slot = mid
  entity = "space_dragon_red_section_entity"  # 原版区段实体，模型动画白嫖
  # component_slot 槽位照抄原版 space_dragon_red_key（定位器在龙翼）
  ...
}
```

> 这样利维坦英雄舰**可自由装配武器**（玩家构筑维度），同时保留巨龙模型。

### 3.4 技能挂载

沿用现有机制：核心槽挂 `br_hero_ship_Core` 组件，每个技能核心组件带 `size_restriction`（限定对应利维坦 ship_size）+ `triggered_ship_modifier`（成长属性，`mult = owner.br_hero_level`）+ `scripted_action`（主动/大招触发）。倍率沿用 `br_hero_ship_skill_{1/2/3}_mult` / `_daymult` / `_cdmult` 体系（`br_hero_skill_values.txt`）。

## 四、成长属性设计（决策 D2 待确认）

### 4.1 数值档位

**不沿用原版利维坦数值**（原版 15 万船体是 Boss 档，给玩家会破坏挑战模式平衡）。按先锋级档位设计：

| 属性 | 先锋级（现状） | 利维坦英雄舰档位 |
|---|---|---|
| 基础船体 | 3000 | 3500～5000（按利维坦定位浮动） |
| 舰队容量 | 8 | 8 |
| 战斗体积 | 32 | 32～48 |
| 速度 | 100 | 80～140（按利维坦机动性） |
### 4.2 每级成长（成长属性 = 每利维坦定制）

沿用 `triggered_ship_modifier` × `owner.br_hero_level` 机制，但**每条利维坦成长方向不同**（示例）：

| 利维坦 | 成长主题 | 每级成长（示例） |
|---|---|---|
| 以太巨龙 | 装甲巨兽 | 船体+600 / 护甲+800 / 减伤+1 / 伤害+10% |
| 恒星吞噬者 | 吸能护盾 | 护盾+1000 / 护盾再生+2% / 敌方护盾易伤 |
| 灵体幽魂 | 相位闪避 | 闪避+3 / 速度+5% / 穿透+2% |
| 次元魔物 | 虚空召唤 | 船体+500 / 召唤强度+5% / 敌方减伤 |
| 毒神 | 腐蚀DOT | 船体+500 / DOT伤害+10% / 敌方回复-5% |
| 自动战舰 | 炮击火力 | 船体+400 / 伤害+15% / 射速+5% |
> 成长数值最终以 `数值设计规范.md` 的强度天花板（单技能 ≤5× 原版、总 DPS ≤15×）校准。

## 五、技能组设计

### 5.1 通用规则

沿用 `总规范.md`：每条利维坦 **Lv2 主动二选一、Lv4 被动二选一、Lv6 大招二选一**，共 8 种组合；冷却/持续时间按 `数值设计规范.md` §7 表；效果强度按 sk1/sk2/sk3 倍率（每英雄等级 +10%）。

### 5.2 参考实现：以太巨龙（完整数值设计）

**主题：烈焰吐息 / 龙威压制 / 装甲巨兽**

| 槽位 | 技能 | 效果（Lv10 满倍率） | 冷却 | 持续 |
|---|---|---|---|---|
| 主动A | 龙息喷吐 | 本星系敌舰受伤 +60%，英雄舰射速 +20% | 180天 | 20天 |
| 主动B | 龙翼护体 | 自身减伤 +20%，护甲再生 +2%/天，仇恨 +1 | 240天 | 30天 |
| 被动A | 龙鳞装甲 | 常驻 船体/护甲 +6000（`ship_hull_add`/`ship_armor_add` ×等级） | 常驻 | — |
| 被动B | 龙威光环 | 本星系敌舰射速 -20%、伤害 -15%（负面光环） | 常驻 | — |
| 大招A | 焚世吐息 | 全星系敌舰 300 范围伤害 + 护甲/护盾压制 2000 + 减速 | 480天 | 40天 |
| 大招B | 巨龙狂暴 | 自身 伤害+150% / 射速+150% → 虚弱期 伤害-60% | 480天 | 20+20天 |
实现文件映射（对齐现有格式，如 `核心-火力.md`）：
* 主动/大招 modifier：`br_leviathan_buffs.txt` + `leviathan_skill_events.txt`
* 被动 modifier：核心组件 `triggered_ship_modifier`（`br_leviathan_cores.txt`）
* 龙威光环：组件 `friendly_aura` 负值实现（参照 `实现参考.md` 控制核心光环方案）

## 六、独立获取线设计（决策 D3）

**「收复线」**——与先锋级发放流程（开局/遗迹）完全独立，每只利维坦一条链：

```
Phase 0 探测  ：星系探索事件发现「异常信号」（每利维坦独立信号源，可随机/固定触发）
Phase 1 接触  ：玩家舰队进入信号星系 → 遭遇事件（利维坦中立或敌意，可先观察）
Phase 2 收复项目 ：特殊项目（如「驯服以太巨龙」），需要科技 + 资源 + 时间（可失败）
Phase 3 获得  ：收复成功 → 发放利维坦英雄舰 + 先锋级退役（D1 方案）
失败分支  ：收复失败 → 利维坦敌对，击杀后掉战利品（不发放）
```

DLC 门槛：Phase 0/3 事件 trigger 加 `host_has_dlc = "Leviathans Story Pack"`（等），无 DLC 玩家完全看不到对应信号。

## 九、风险与待验证点（以事实为准，不猜测）

1. **模型渲染**：克隆 ship_size + 引用原版区段实体后，模型/动画是否正常加载——必须游戏内实测（`reload stats` + 控制台给船）
2. **`hero_ship` 块 + 非原版 entity 组合**：巨兽先例是 kaiju，理论可行，实测确认
3. **`is_space_object` 语义**：原版利维坦多为 `is_space_object = yes`，克隆为英雄舰时是否保留待实测（先锋级无此项）
4. **区段槽位定位器**：龙翼定位器对玩家武器是否正常挂载（原版是 NPC 舰，需实测）
5. **`has_dlc` 触发格式**：事件内用 `host_has_dlc`（已核实原版用法），ship_size 的 `potential_country` 内用 `has_dlc`——实现时核对
6. **技能 UI**：利维坦技能按钮复用现有 `br_level_ui_hero_skill_buttons` 机制，技能图标先复用原版 GFX（`GFX_ship_part_*`），专属图标后续做
7. **先锋级退役**：D1 方案需处理先锋级回收（flag 转移/舰船移除），注意 `heroship.2` XP 事件的 `is_ship_size = br_vanguard` 条件需同步扩展
