# 以太巨龙换色方案（2026-09-12 调查）

> 缘起：V1 参考实现只给了红龙（原版 Ether Drake 外观）。讨论「生成时能否随机换色」引出本调查。
> 现状：换色未实装，实际执行的是路径 ③（固定红）——`lev_ship_sizes.txt` 的 entity 为单值 `lev_drake_entity`（自制克隆实体链，含 locator_mesh 与独立动画注册，非直接引用原版 `space_dragon_red_entity`），`lev_drake.asset` 的 ship_color 为红（hsv 0.07 1.0 0.75）。D6 正式拍板仍待用户决定。
> 本文档为独立专题，主设计文档指向此处。

## 一、事实核查（已核实，非猜测）

| 项 | 结论 | 证据 |
|---|---|---|
| 模型几何复用 | 红 / 蓝 / 紫三条龙共用同一 .mesh 几何（`guardian_01_space_dragon.mesh`），仅 meshsettings 的 diffuse 贴图不同 | `guardian_01_space_dragon.gfx` 三套 mesh 实体均 `file =` 同一 mesh |
| 三种颜色实体齐备 | `space_dragon_{red,blue,purple}_entity`（含各自区段实体）全部存在于原版 asset，可直接引用 | `guardian_01_space_dragon.asset` L2 / L534 / L990 |
| 紫龙原版未启用 | 原版没有任何 ship_size / 全局设计引用紫龙（红 = Ether Drake，蓝 = Grand Dragon）；紫龙实体是「留好但未用」的现成资产 | 原版 `common/ship_sizes` 全量 grep `space_dragon_purple` 0 匹配 |
| 引擎换色机制 | 原版 .asset / .gfx 中不存在 random / chance 用于选择颜色或网格；唯一 chance 仅用于动画状态选择，不可用于持续换色 | 同目录 grep 0 匹配 |
| 设计器状态 | `lev_drake` 明确 `is_designable = yes`（D4） | `lev_ship_sizes.txt` L105 |

关键推论：模型层无法「随机一张贴图」。所谓「随机外观」只能靠在生成事件层，从若干预定义颜色变体中随机挑一个——而每个颜色变体必须是独立的实体（已齐备），最终落到 ship_size 的 `entity` 字段上。

## 二、约束：为什么不能用 ship_size 随机（对可设计英雄舰）

- `is_designable = yes` 时，每个 ship_size 都会在玩家舰船设计器里占一个条目。换 N 种颜色 = 设计器列表里出现 N 条「换色版巨龙」，污染列表。
- 武器槽位（区段模板）要按 ship_size 配，N 个 ship_size = N 套武器装配配置，维护与玩家构筑都乱。

这条约束只在 `is_designable = yes` 时成立。`is_designable = no`（事件直接授予成品）时，ship_size 不进设计器，多 ship_size + `random_list` 零污染——见路径 ①。

## 三、三条可行路径（含取舍）

| 路径 | 做法 | 能否每次生成随机 | 设计器污染 | 玩家能否装配武器 | 状态 |
|---|---|---|---|---|---|
| ① 真随机·授予成品 | `is_designable = no`，收复事件用 `random_list` 在多套「同模型不同 entity 的 ship_size / 全局设计」里抽一个，直接授船 | 是 | 无 | 否（成品固定配装） | 备选 |
| ② 可设计·按文化分色 | 保留 `is_designable = yes`，为每种 `graphical_culture` 建分色 entity；颜色由帝国美术风格决定 | 否（同文化恒同色） | 无 | 是 | 备选 |
| ③ 可设计·固定单色 | 保留 `is_designable = yes`，`entity` 锁死红 | 否 | 无 | 是 | 已按默认执行 |

补充：「玩家可选色 + 可设计」在当前引擎下无法干净实现（entity 挂在 ship_size 上而非设计上，单 ship_size 无法靠设计改 entity；要么多 ship_size 污染，要么放弃装配），列为 V2 待议。

## 四、若未来换色（路径 ① 或 ② 实装要点，均需实测）

- 路径 ①：`lev_drake` 的 `is_designable` 改 `no` + 收复事件 `random_list` 抽色 + 多套 `global_ship_design`（各绑一种颜色的 ship_size）；成品配装改为事件内写死。
- 路径 ②：ship_size 的 `entity` 是单值字符串，无法在一个 ship_size 内按文化条件切换。两种做法二选一：利用 `graphical_culture` 的 ship entity 覆盖表（干净，但需确认自定义 ship_size 能否进该覆盖表）；或建多个 culture 限定的 ship_size 变体，靠 `potential` 让同文化只暴露一个。
- 紫龙启用点：把某分支的 entity 换成 `space_dragon_purple_entity` / `_purple_section_entity`，其余动画 / 粒子自动跟随。注意 mod 版已改为自制 `lev_drake_entity` 克隆链，换色应基于克隆链做分色变体，而不是回引原版实体。

D6 拍板「不做换色」时，本文档可归档删除。
