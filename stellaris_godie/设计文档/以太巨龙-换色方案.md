# 以太巨龙换色方案（2026-09-12 调查）

> 缘起：V1 参考实现只给了红龙（原版 Ether Drake 外观）。讨论「生成时能否随机换色」引出本调查。
> 结论先行：引擎没有原生的「随机纹理 / 换色」机制，且本龙 `is_designable = yes`（D4），
> 所以「用 ship_size 随机」这条路被排除（会污染玩家设计器列表 + 武器装配翻倍）。
> 本文档为独立专题，主设计文档 §七 决策项 D6 指向此处。

## 一、事实核查（已核实，非猜测）

| 项 | 结论 | 证据 |
|---|---|---|
| 模型几何复用 | 红 / 蓝 / 紫三条龙共用同一 .mesh 几何（`guardian_01_space_dragon.mesh`），仅 meshsettings 的 diffuse 贴图不同 | `guardian_01_space_dragon.gfx` 三套 mesh 实体 `space_dragon_{red,blue,purple}_mesh` 均 `file =` 同一 mesh |
| 三种颜色实体齐备 | `space_dragon_red_entity` / `_blue_entity` / `_purple_entity`（含各自区段实体）全部存在于原版 asset，可直接引用，无需新资产 | `guardian_01_space_dragon.asset` L2 / L534 / L990 |
| 紫龙原版未启用 | 原版没有任何 ship_size / 全局设计引用紫龙（红 = 以太巨龙（Ether Drake），蓝 = 巨龙（Grand Dragon））；紫龙实体是「留好但未用」的现成资产 | `common/ship_sizes` 全量 grep `space_dragon_purple` 0 匹配 |
| 引擎换色机制 | 原版所有 `.asset` / `.gfx` 中不存在 `random` / `chance` 用于选择颜色 / 网格；唯一 `chance` 仅用于动画状态选择（如轰炸姿态切换），不可用于持续换色（会让颜色在 idle / moving / death 之间乱跳） | 同目录 grep `random\|chance` 0 匹配 |
| 设计器状态 | `br_leviathan_drake` 明确 `is_designable = yes`（主文档 §3.2，D4） | 主设计文档 §3.2 L111 |

关键推论：模型层无法「随机一张贴图」。所谓「随机外观」只能靠在生成事件层，从若干预定义颜色变体中随机挑一个——而每个颜色变体必须是独立的实体（已齐备），最终落到 ship_size 的 `entity` 字段上。

## 二、约束：为什么不能用 ship_size 随机（对可设计英雄舰）

用户已明确否定「多 ship_size 各自一种颜色、生成时 `random_list` 抽一个」作为可设计英雄舰的换色手段，理由成立：

- `is_designable = yes` 时，每个 ship_size 都会在玩家舰船设计器里占一个条目。换 N 种颜色 = 设计器列表里出现 N 条「换色版巨龙」，污染列表。
- 武器槽位（区段模板）要按 ship_size 配，N 个 ship_size = N 套武器装配配置，维护与玩家构筑都乱。
- 因此：对可设计英雄舰，换色不能靠增加 ship_size。

注意：这条约束只在 `is_designable = yes` 时成立。`is_designable = no`（事件直接授予成品英雄舰）时，ship_size 根本不进设计器，多 ship_size + `random_list` 反而零污染——见路径 ①。

## 三、三条可行路径（含取舍）

| 路径 | 做法 | 能否每次生成随机 | 设计器污染 | 玩家能否装配武器 | 备注 |
|---|---|---|---|---|---|
| ① 真随机·授予成品 | `is_designable = no`，收复事件用 `random_list` 在多套「同模型不同 entity 的 ship_size / 全局设计」里抽一个，直接授船 | 是（每次独立） | 无（不进设计器） | 否（成品固定配装） | 唯一能「真随机又不污染」的路；代价是放弃玩家构筑维度 |
| ② 可设计·按文化分色 | 保留 `is_designable = yes`，为每种 `graphical_culture` 建 `<culture>_br_leviathan_drake_entity`，各自指向红 / 蓝 / 紫 mesh；颜色由帝国美术风格决定 | 否（按文化确定，同文化恒同色） | 无（仍是 1 个 ship_size） | 是 | 视觉有区分但非随机；紫龙在此可被启用 |
| ③ 可设计·固定单色 | 保留 `is_designable = yes`，`entity` 锁死一种（默认红 = 原版 Ether Drake 外观） | 否 | 无 | 是 | 最简单、零额外资产；无视觉变化 |

补充（路径 ② 的「玩家可选色」变体）：
若想让玩家「在收复时从几种颜色里挑一个」且仍保留装配，需要单 ship_size + 多套全局设计（每色一套、各自固定 entity）——但 entity 挂在 ship_size 上而非设计上，单 ship_size 无法靠设计改 entity。所以「玩家可选色 + 可设计」在当前引擎下无法干净实现（要么多 ship_size 污染，要么放弃装配）。建议 V1 不做，列为 V2 待议。

## 四、推荐（待拍板，不擅自定）

- V1 参考实现（以太巨龙）：默认走路径 ③（固定红）起步——先跑通模型 / 技能 / 收复线，换色留接口。
- 若要「每条龙颜色各异、一眼区分」且不牺牲装配：路径 ②（按 gfx_culture 分色）最稳，紫龙可作为某文化的专属色启用。
- 若「随机惊喜」优先级高于玩家装配：路径 ①（授予成品 + random_list），但需把该龙从 `is_designable` 挪出，且配方 / 配装改为事件授予。

决策项 D6（见主文档 §七）：选哪条路、是否启用紫龙，需用户拍板后再落代码（禁止擅自决定）。

## 五、落实时的最小改动点（任一路径，具体 hook 待游戏内实测）

- 路径 ③：维持现状，仅确认 `entity = "space_dragon_red_entity"` 为最终外观（主文档 §3.2 L94）。
- 路径 ①：`br_leviathan_drake` 的 `is_designable` 改 `no` + 收复事件 `random_list` 抽色 + 多套 `global_ship_design`（各绑一种颜色的 ship_size）；注意成品配装改为事件内写死。
- 路径 ②：ship_size 的 `entity` 是单值字符串，无法在一个 ship_size 内按文化条件切换。两种务实做法二选一（均需实测）：
  1. 利用 `graphical_culture` 的 ship entity 覆盖表，让每种文化的同名 entity 指向不同颜色 mesh（干净，但需确认自定义 ship_size 能否进该覆盖表）；
  2. 退而建多个 culture 限定的 ship_size 变体（各 `graphical_culture` + `potential_country` 限定，仍 `is_designable = yes`），靠 `potential` 让同文化只暴露一个——可避免设计器出现多个条目。

紫龙启用点：把某文化（或路径 ① 的某个随机分支）的 entity 换成 `space_dragon_purple_entity` / `_purple_section_entity` 即可，其余动画 / 粒子（asset L990+ 已齐备）自动跟随。
