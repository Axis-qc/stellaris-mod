# 总规范

> 英雄舰核心技能系统的总体规则、设计约束与数值参考。

---

# 一、系统定位

## 1.1 母舰与英雄舰分工

### 母舰

母舰是玩家的战略基地与后勤核心。

主要职责：

* 造船
* 补给
* 资源转化
* 战斗支援
* 玩家基础生存保障
* 作为玩家的移动后方

母舰不承担主要流派构筑职责。

### 英雄舰

英雄舰是玩家的战斗流派核心。

主要职责：

* 选择核心类型
* 决定战斗风格
* 搭载主动技能、被动技能和大招
* 通过独立等级系统成长
* 在 PvE 推进和 Boss 战中发挥关键作用

英雄舰不是母舰。
母舰负责"生产与补给"，英雄舰负责"战斗与构筑"。

# 二、英雄舰核心系统总规则

## 2.1 核心选择

每个玩家只能选择 **1 个英雄舰核心**。

核心决定英雄舰的主要玩法方向。

## 2.2 技能选择

每个核心提供 **2 个主动技能**、**2 个被动技能**、**2 个大招**。玩家在对应等级各选其一：

* Lv2：主动技能二选一
* Lv4：第一个被动技能
* Lv6：大招二选一
* Lv10：第二个被动技能

共可组成多种技能组合。

## 2.3 英雄舰等级系统

每个玩家的英雄舰拥有独立等级系统。

英雄舰**无最高等级限制**。12 级后每积累 5000 XP 消耗并升 1 级。

每个玩家的英雄舰等级独立计算，不共享。

## 2.4 英雄舰经验获取

击杀敌舰获得经验（`heroship.2`）：

| 敌舰类型 | XP |
|---------|---:|
| Boss     | 500 |
| 战列舰   | 40 |
| 巡洋舰   | 20 |
| 驱逐舰   | 10 |
| 护卫舰   | 5 |
| 其他     | 3 |

## 2.6 通用等级属性成长

英雄舰核心组件（`br_vanguard_auras.txt`）提供基础属性，按英雄等级线性缩放：

| 属性 | 成长方式 | 每级加成 | 例：Lv1 | 例：Lv12 |
|------|---------|--------:|-------:|--------:|
| 船体 | `ship_hull_add = 500` × **level** | +500 | 500 | 6000 |
| 护甲 | `ship_armor_add = 500` × **level** | +500 | 500 | 6000 |
| 护盾 | `ship_shield_add = 500` × **level** | +500 | 500 | 6000 |
| 减伤 | `ship_damage_reduction_add = 1` × **level** | +1 | 1 | 12 |
| 武器伤害 | `ship_weapon_damage = 0.10` × **level** | +10% | 10% | 120% |
| 船体再生 | `ship_hull_regen_add_perc = 0.01` × **level** | +1%/天 | 1%/天 | 12%/天 |
| 护甲再生 | `ship_armor_regen_add_perc = 0.01` × **level** | +1%/天 | 1%/天 | 12%/天 |

实现：`triggered_ship_modifier` + `mult = owner.br_hero_level`，一次施加，等级自动缩放。

## 2.7 技能倍率与持续时间

所有技能效果受两套倍率同时放大（代码 `br_kill_stack_values.txt`）：

```
等级乘区    = hero_level × 0.1
独立乘区    = br_skill_N_mult_player（默认0，临时效果可修改）
最终倍率    = 1 + 等级乘区 + 独立乘区
```

**等级乘区**：在 `br_kill_stack_values.txt` 中自动按等级计算，不依赖事件手动设变量。  
**独立乘区**：`br_skill_N_mult_player` 留作独立乘区，可被临时 buff/debuff 或测试法令修改（如测试法令 `change_variable br_skill_1_mult_player = 0.5`）。

**效果倍率**（`mult`）放大 modifier 数值；**持续时间倍率**（`time_multiplier/daymult`）放大技能持续天数。

例：Lv12 时等级乘区 = 1.2，独立乘区=0，最终倍率 = ×2.2。

# 三、设计约束

## 3.1 危险区限制

危险区是星系级状态，只有两种情况：

* 是危险区
* 不是危险区

危险区相关技能只能作为：

* 撤离
* 保命
* 临时减伤
* 紧急赶路

不设计长期顶毒流。

## 3.2 缩圈机制限制

缩圈路线在开局扩圈时已经固定，后续只是反向收缩。

不设计：

* 预测下一阶段安全区方向
* 显示未来圈路线
* 改变缩圈路线
* 临时改变安全区中心

## 3.3 奖励机制限制

奖励通常在事件触发时随机生成，不天然存在"下一次奖励"。

不设计：

* 提前查看下一次奖励
* 预言未来奖励
* 直接锁定尚未生成的奖励

允许设计：

* 当前奖励重抽
* 当前奖励额外选项
* 提高某类奖励权重
* 获得一次额外奖励

# 十五、开发优先级建议

## 第一批核心

优先实现机制简单、最能验证核心循环的核心：

* 火力核心
* 防御核心
* 支援核心
* 命运核心

## 第二批核心

等基础玩法稳定后加入：

* 献祭核心
* 机动核心
* 控制核心
* 掠夺核心

## 第三批核心

作为扩展内容加入：

* 航母核心
* 指挥核心

# 十六、总结

母舰负责生产、补给和战略后勤。
英雄舰负责战斗技能、核心选择和个人成长。

每个玩家拥有独立英雄舰等级，无最高上限。
每个核心提供 2 主动、2 被动、2 大招，玩家在对应等级各选其一。
通过等级成长、资源奖励和战斗推进，英雄舰逐渐形成独特流派。

核心分工原则：
* 火力核心 — 杀得快（攻击向）
* 防御核心 — 活得久 + 修得回（生存+修复向）
* 支援核心 — 协同指挥，让现有舰队更强（增益+恢复向）
* 掠夺核心 — 以战养战、侵略性资源获取（资源掠夺向）
* 指挥核心 — 多舰队协同作战（战术增益向）
* 其余核心 — 各自独立玩法方向

该系统的目标是让「挑战虚空」不仅是缩圈与 Boss 战，而是一个具有 Roguelike 构筑感的舰队成长模式。
