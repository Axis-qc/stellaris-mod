# 利维坦系统（Leviathan System）

> 复用原版利维坦模型做玩家可拥有的利维坦舰：模型/动画零成本，只需设计技能组与成长机制。
> 本档为「利维坦系统」的**通用框架与技能组设计方法论**，对所有利维坦共用。
> 各利维坦的**具体方案**（噬星者、以太巨龙等）分别独立成文，见文末「文档关系」。
> 数值基准：`数值设计规范.md`。

## 文档关系（避免混淆）

- **本文件** = 利维坦系统的**通用框架 + 技能组设计方法论**（所有利维坦共用，不含任何单只利维坦的具体数值方案）。
- `利维坦背景设定.md` = 各利维坦的**原版背景设定**（取自原版守卫者事件/策展人情报），作为技能组设计的依据。
- `噬星者.md` = 噬星者（Stellar Devourer）的**具体方案**，已实现并实测通过。
- `以太巨龙.md` = 以太巨龙（V1 参考实现）的**具体技能 / 成长 / 获取方案**。
- `以太巨龙-换色方案.md` = 以太巨龙换色专题（决策项 D6）。

> 命名空间：`lev_*`（独立，不复用 `br_hero_*`）。不要与现有「英雄舰系统（先锋级 `br_vanguard`）」混淆——两者是不同系统，关系见 §七 D1。

## 一、系统定位

### 1.1 一句话

**利维坦系统** = 用原版利维坦的 3D 模型 + 区段实体，克隆出玩家可拥有、可升级、带独立技能组的利维坦舰。每条利维坦 = 一艘「自带核心的利维坦舰」。

### 1.2 与现有英雄舰系统（先锋级）的关系 [D1 待拍板]

现有英雄舰系统（先锋级 `br_vanguard`，命名空间 `br_hero_*`）是独立存在的另一套系统。

利维坦系统是**另一套独立框架**（命名空间 `lev_*`），自身的克隆 / 成长 / 技能机制不依赖先锋级。两者关系——利维坦是否作为先锋级的进阶形态、是否并存——是 §七 决策 D1，**本文件不预设结论**：无论 D1 取哪个，利维坦系统自身的机制不变。

> 易混淆点：不要把「利维坦系统」当成「英雄舰系统」的一部分或分支。它复用的是引擎的 `hero_ship` 块与技能倍率**约定**（如 `br_hero_ship_skill_*_mult` 体系），但代码命名空间、获取线、变量全部独立。

## 二、可行性结论（已调查确认 [已实现]）

### 2.1 模型复用机制

原版利维坦模型分两层（`gfx/models/ships/guardians/`）：

| 层 | 作用 | 例（以太巨龙） |
|---|---|---|
| 舰船实体 | 定位器/命中判定 | `space_dragon_red_entity`（ship_size 的 `entity` 字段引用） |
| 区段实体 | 实际模型+动画 | `space_dragon_red_section_entity`（区段模板引用） |
**原版先例**：`24_reanimated_leviathans.txt` 的复活利维坦就是玩家拥有、`entity` + 区段实体组合渲染的；`27_biogenesis_crisis.txt` 的巨兽（kaiju）更是 `hero_ship = {}` 块 + 玩家拥有的利维坦舰。**模型复用零成本，已证实可行。**

## 三、舰船架构设计（克隆方法）

### 3.1 原则：克隆，不碰原版

**绝对不修改 `11_leviathans.txt` 等原版文件**——那会破坏原版利维坦遭遇（守卫者 AI、剧情事件依赖原版 ship_size 名）。全部新写克隆文件：

| 新文件 | 内容 |
|---|---|
| `common/ship_sizes/br_leviathan_ships.txt` | 每个利维坦一个克隆 ship_size（命名 `br_leviathan_<名>`） |
| `common/section_templates/br_leviathan_sections.txt` | 克隆区段模板（`ship_size = br_leviathan_<名>`，引用原版区段实体） |
| `common/component_templates/br_leviathan_cores.txt` | 每利维坦专属技能核心组件（挂主动/被动/大招 scripted_action） |
| `common/static_modifiers/br_leviathan_buffs.txt` | 技能 modifier 定义 |
| `events/leviathan_acquire_events.txt` | 独立收复线事件 |
| `events/leviathan_skill_events.txt` | 技能触发事件 |
| `localisation/simp_chinese/br_leviathan_l_simp_chinese.yml` | 本地化（**UTF-8 BOM**） |
### 3.2 ship_size 克隆骨架（以太巨龙为参考示例）

> 以太巨龙是 V1 参考实现，下方用它的 ship_size 作**克隆骨架示例**；其余利维坦的同类文件见各自方案文档。

```pdx
br_leviathan_drake = {
  entity = "space_dragon_red_entity"  # 舰船实体（原版）
  can_be_inspected = yes
  hull_scale = 1  # 原版比例即可，可调
  max_speed = 100
  acceleration = 0.3
  rotation_speed = 0.4
  collision_radius = 15
  max_hitpoints = 4000  # 数值档位见 §4，不沿用原版 15 万
  combat_size_multiplier = 32
  size_multiplier = 32
  fleet_slot_size = 8
  section_slots = { "mid" = { locator = "part1" } }
  num_target_locators = 4
  never_lost = yes
  never_mia = yes
  is_space_station = no
  class = shipclass_military
  is_designable = yes  # 决策 D4：可设计，玩家可装配武器
  required_component_set = "br_hero_ship_Core"  # 复用英雄舰核心槽（仅槽位约定，命名空间仍 lev_/br_leviathan_）
  hero_ship = {
  hero_ship_fleet_background = "GFX_fleet_view_behemoth_stage_2"  # 复用原版背景
  capabilities = { can_repair can_upgrade }
  }
  components_add_to_cost = no
  resources = { ... }  # 按先锋级档位
  potential_country = { has_country_flag = br_leviathan_drake_unlocked }
}
```

### 3.3 区段模板克隆（复用原版区段实体 + 槽位，参考示例）

原版龙区段（`space_dragon_red_key`）自带 1 XL + 8 中 + 4 点防 + 2 辅助 + 4 大型辅助槽，武器定位器在龙翼上。克隆时保留原版槽位布局、替换 `ship_size`：

```pdx
ship_section_template = {
  key = "br_leviathan_drake_key"
  ship_size = br_leviathan_drake
  fits_on_slot = mid
  entity = "space_dragon_red_section_entity"  # 原版区段实体，模型动画白嫖
  # component_slot 槽位照抄原版 space_dragon_red_key（定位器在龙翼）
  ...
}
```

> 这样利维坦舰**可自由装配武器**（玩家构筑维度），同时保留巨龙模型。

### 3.4 技能挂载（通用机制）

沿用现有机制：核心槽挂 `br_hero_ship_Core` 组件，每个技能核心组件带 `size_restriction`（限定对应利维坦 ship_size）+ `triggered_ship_modifier`（成长属性，`mult = owner.lev_<TYPE>_growth_level`）+ `scripted_action`（主动/大招触发）。倍率沿用 `br_hero_ship_skill_{1/2/3}_mult` / `_daymult` / `_cdmult` 体系（`br_hero_skill_values.txt`）。

## 四、成长值系统（通用框架）

> 所有利维坦共用一套成长值机制，**参数化到每只利维坦**（`<TYPE>` 标识，如 `stellarite` / `drake`）。
> 噬星者是第一个接入实例，其具体变量与 UI 见 `噬星者.md`；本节只描述机制本身。

### 4.1 一句话

利维坦除了复用英雄舰的等级乘数约定，还有一条**自己的成长值**：一条是打出来的（战斗击杀），一条是喂出来的（玩家在利维坦界面投入营养资源）。两条途径汇进同一个成长值，成长值决定成长等级，成长等级决定个体战斗力。

### 4.2 数据层（国家级变量，每只利维坦一套）

| 变量 | 含义 | 初值 |
|---|---|---|
| `lev_<TYPE>_growth` | 累积成长值（只往里加，升级时扣除阈值） | 0 |
| `lev_<TYPE>_growth_level` | 成长等级（1 级起，**战斗力乘数**） | 1 |
| `lev_<TYPE>_growth_next` | 下一级所需成长值（UI 显示用） | 10 |
| `lev_<TYPE>_feed_level` | 营养档位 0=停止 1=低 2=中 3=高 | 0 |
| `lev_<TYPE>_cost_low/mid/high` | 当月各档消耗 = 等级 × 5 / 10 / 20 | — |
| `lev_<TYPE>_gain_low/mid/high` | 当月各档收益 = 固定值 低4/中8/高16 | — |

> **每只利维坦一套，互不干扰**——`<TYPE>` 是利维坦标识。
> 变量名拼接有**原版先例**：`shroud_shadows_scripted_effects.txt` 就在用
> `check_variable = { which = $TYPE$_government_weight value < 1 }`。
> 因此所有效果都做成了参数化调用：`lev_growth_check_level = { TYPE = stellarite }`。

阈值与英雄舰经验完全同构：

| 段 | 阈值 |
|---|---|
| 1→2 … 11→12 | 10 / 30 / 70 / 130 / 220 / 350 / 520 / 750 / 1050 / 1500 / 2200 |
| 12 级后 | 每级固定 5000，**无上限** |

升级时按英雄舰同款做法**扣除阈值**（成长值本质是经验，不是永不消耗的计数）；
「只增不减」指的是**没有任何机制会把已获得的成长值扣回去**。

### 4.3 来源一：战斗（通用）

事件 `lev.20`，挂在 `on_ship_destroyed_perp`，逻辑逐字复用英雄舰 `heroship.2`：

> 同星系内有利维坦舰船 → 击杀敌对舰船 → 成长值 += 被击杀舰船 `max_hp ÷ 100`（向上取整）

「这艘船是不是利维坦」由 `lev_is_leviathan_ship`
（`common/scripted_triggers/lev_leviathan_triggers.txt`）判定。
**新增一只利维坦要动四处**：① `lev_is_leviathan_ship` 的 `OR` 加一行 `is_ship_size`；
② `lev.20` 加一个 `if` 分支（判定哪只在击杀星系内，给谁入账）；
③ `lev_feed_settle_all` 加一行；
④ UI 卡片槽（`lev_ui_buttons.txt` + `br_level_view.gui`）。
其余调用点全部是 `$TYPE$` 参数化的，不需要改。

### 4.4 来源二：营养（每利维坦定制资源）

玩家在利维坦界面自行选择档位，每月结算一次（`on_monthly_pulse_country` → `lev.21`）。

设当前成长等级为 L：

| 档位 | 每月消耗 | 每月获得成长 |
|---|---|---|
| 低 | L × 5 | L × 1 |
| 中 | L × 10 | L × 2 |
| 高 | L × 20 | L × 4 |

换算率恒为 **5 资源 : 1 成长**，三档只是速率倍数不同。
消耗与收益**都随等级放大**，因此高等级不会因为阈值变大而停滞。

* **资源类型按利维坦定制**：例如噬星者吃**能量币**，其余利维坦各自定义
  （在 `lev_feed_settle` 里加分支或换资源）。
* **资源不足**：当月中止 —— 不涨成长、不降档、不提示。
* **节奏测算**（纯营养、从 1 级到 12 级）：低档约 70 年，中档约 34 年，高档约 17 年。

### 4.5 成长值 → 战斗力

沿用 `triggered_ship_modifier`，乘数直接用**该利维坦的成长等级**：

```
triggered_ship_modifier = {
    modifier = { ... 每级成长 }
    mult = owner.lev_<TYPE>_growth_level
}
```

* **用 `level`，不用 `level − 1`**：利维坦没有普通舰队陪跑，
  开局就白送一级加成是刻意的补偿（数值后续再调）。
* **绝不能用 `growth`**：它是无上限累积值（12 级需 2200 点），
  直接当乘数会算出几十万，这是最关键的坑。

> **数值天花板提醒**：12 级后斜率**不衰减**（+5%/级 一直加）是已确认的设计选择，
> 它会突破《数值设计规范》§10.1 的「单技能 ≤5× 原版 / 总 DPS ≤15×」。
> 若后续要收紧，改动点只有一处：把乘数改成软上限，或让 12 级后斜率减半。

### 4.6 UI（利维坦页签）

在现有 `br_level_view.gui` 底部标签栏**新增「利维坦」页签**，每只利维坦一张小卡片（两列横向、纵向可滚动）。

单张卡片内容：

| 行 | 内容 |
|---|---|
| 标题 | 利维坦名 |
| 第 1 行 | 成长等级 N　成长值 A / B |
| 第 2 行 | 三档消耗一览（低 / 中 / 高 各多少资源） |
| 按钮行 | 低档 / 中档 / 高档 / 停止（已选档位自动灰化） |

* 未解锁的卡靠 `lev_card_<TYPE>` 的 `potential` 整体隐藏。
* **没有「成长规则」文字面板**——规则靠卡片上的数字自解释，界面保持简洁。
* 按钮效果在 `common/button_effects/lev_ui_buttons.txt`，每只利维坦各一套；
  每个按钮自带 `potential` 页签判断，否则会跨页常显。

### 4.7 舰队 UI 状态栏（custom_state_loc_prefix 机制）

卡片面板要专门开控制中心才看得到；**舰队界面左侧的状态栏**则是选中利维坦就能看到成长等级，
实用性更高。机制来自原版 `hero_ship` 的子字段（原版仅 `behemoth_01~04` / 噬天巨兽用过）：

```pdx
hero_ship = {
    custom_state_loc_prefix = "LEV_<TYPE>_STATE"
}
```

* 引擎自动拼 `LEV_<TYPE>_STATE_title` 与 `_value` 两个键（`_tt` 是可选提示），
  作用域是**选中的舰队**。
* 因此 scripted_loc 里用 `owner.<变量>` 读国家级成长数据（利维坦是单舰舰队，`owner` 必然是国家）。
* 数值输出用有官方注释背书的写法：
  `defined_text = { name = X  value = value:<script_value> }`
  （见原版 `common/scripted_loc/000_example.txt` L27-31）。
* 显示格式：**成长状态 ｜ 3 级　16/70（+20）**——等级、当前/下级阈值、当前档位的每月营养收益（停止档显示 +0）。
* **档位收益的取值不能写在 script_value 里**：script_value 只支持
  `base / add / subtract / multiply / divide / trigger`，**不支持 `if = {}` 条件分支**
  （原版全部 script_values 均未用过 `if`，插件会报 ERROR——已实测）。
  因此档位选择放在**效果层**完成：效果把当前档位收益算进
  `lev_<TYPE>_gain_current`，营养按钮点击时也即时同步这个变量，
  script_value 只负责 `add = owner.lev_<TYPE>_gain_current` 读出来。
* 仅在**单舰舰队**出现；状态栏启用时会隐藏领袖头像与信息。

完整链路（以噬星者 `LEV_STELLARITE_STATE` 为例，详见 `噬星者.md`）：

```
ship_size.hero_ship.custom_state_loc_prefix
  → 本地化 LEV_<TYPE>_STATE_title / _value
  → defined_text GetLevState*<TYPE>
  → script_value lev_state_*_<TYPE>
  → 国家变量 lev_<TYPE>_growth / _level / _next / gain_current
```

> **JetBrains 插件会在这里误报**：`custom_state_loc_prefix` 那行会报
> `WEAK WARNING 无法解析值表达式 ...（期望匹配：localisation）`。
> 已用原版自己的值 `HANGER_STATE` 做对照探针确认——**连原版写法也报同一条警告**，可以忽略。

## 六、独立获取线设计（通用框架）

**「收复线」**——与先锋级发放流程（开局/遗迹）完全独立，每只利维坦一条链：

```
Phase 0 探测  ：星系探索事件发现「异常信号」（每利维坦独立信号源，可随机/固定触发）
Phase 1 接触  ：玩家舰队进入信号星系 → 遭遇事件（利维坦中立或敌意，可先观察）
Phase 2 收复项目 ：特殊项目（如「驯服以太巨龙」），需要科技 + 资源 + 时间（可失败）
Phase 3 获得  ：收复成功 → 发放利维坦舰
失败分支  ：收复失败 → 利维坦敌对，击杀后掉战利品（不发放）
```

DLC 门槛：Phase 0/3 事件 trigger 加 `host_has_dlc = "Leviathans Story Pack"`（等），无 DLC 玩家完全看不到对应信号。

> 注：噬星者的实际获取已改为**国民理念门控**（详见 `噬星者.md` §6.5），不走本收复线；本框架描述通用的「收复线」思路，供后续利维坦参考。

## 九、风险与待验证点（通用，以事实为准，不猜测）

1. **模型渲染**：克隆 ship_size + 引用原版区段实体后，模型/动画是否正常加载——必须游戏内实测（`reload stats` + 控制台给船）
2. **`hero_ship` 块 + 非原版 entity 组合**：巨兽先例是 kaiju，理论可行，实测确认
3. **`is_space_object` 语义**：原版利维坦多为 `is_space_object = yes`，克隆为玩家舰时是否保留待实测（先锋级无此项）
4. **区段槽位定位器**：龙翼定位器对玩家武器是否正常挂载（原版是 NPC 舰，需实测）
5. **`has_dlc` 触发格式**：事件内用 `host_has_dlc`（已核实原版用法），ship_size 的 `potential_country` 内用 `has_dlc`——实现时核对
6. **技能 UI**：利维坦技能按钮复用现有 `br_level_ui_hero_skill_buttons` 机制，技能图标先复用原版 GFX（`GFX_ship_part_*`），专属图标后续做
7. **`custom_state_loc_prefix` 误报**：JetBrains 插件会误报，已用原版 `HANGER_STATE` 对照确认可忽略（§4.7）
> 各利维坦专属风险见其方案文档。
